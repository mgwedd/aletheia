# Project memory

Concise, non-obvious rules for this repo. (Obvious stuff omitted on purpose.)

## Attribution / contribution
- **Michael Wedd is the sole contributor of record.** No Claude attribution in
  commits, PR titles, or PR bodies. No `Co-Authored-By: Claude`, no
  `Claude-Session:` trailer, no "Generated with/by Claude Code" footer.
- **Commit as Michael, not "Claude".** Fresh clones default the git identity to
  Claude — set it first: `git config user.name "Michael Wedd"` /
  `user.email "michael.wedd@gmail.com"`. Re-author any Claude-authored commits
  (`git commit --amend --reset-author`, or `git rebase <base> --exec`) and
  force-push your own branch.
- The PR-create tool **server-appends** a "Generated by Claude Code" footer to
  the body; after creating a PR, edit the body to strip it (it won't re-append).
- No model identifier (e.g. "Opus", model IDs) in anything pushed to the repo.

## Pull requests
- **Ready → open (not draft).** Only keep a PR in draft while actively working on
  it; a PR that's ready for Michael to review/merge is a normal open PR.

## Acceptance criteria and UI tests (see `.claude/rules/acceptance-tests.md`)
- `docs/spec/ACCEPTANCE-CRITERIA.md` is the product's requirements; the
  acceptance and XCUI tests are their executable form. Every feature or
  substantial change ships a criterion + acceptance test + XCUI test, named by ID.
- **Tests change when behaviour changes, and only then.** A refactor that keeps
  behaviour should touch at most the harness (small DSL/driver/fixture
  adjustments); edits to test bodies mean the tests are coupled to internals.
  The corollary: a feature change that leaves its acceptance tests untouched
  means coverage is missing — add or update the criterion and its tests.

## Names & project generation
- Product/display name, Xcode target, scheme, and Swift module are all
  **Aletheia**; the bundle ID is **`com.astrealabs.aletheia`** (helpers and tests nest under it). The app source dir
  is `Sources/App`, the test source dir is `Tests/AletheiaTests`.
- **No `.xcodeproj` is checked in.** `project.yml` (repo root) is the source of
  truth; XcodeGen generates the project. Edit `project.yml`, not a pbxproj.
- Deployment target: **macOS 14**.

## Privacy / architecture invariants (non-negotiable)
- **PHI never leaves the Mac.** No analytics/telemetry/servers. The main app
  has **no network entitlement**; the only outbound calls are made by the bundled
  network helper (`Sources/NetworkHelper`, a sandboxed XPC service): the update
  check, the daily signed license revocation list (only while update checks
  are on) and opt-in model downloads — none carries PHI or a license key. The app asks it for
  fixed assets by integer ID; it takes no URL, string or data. Don't add
  `network.client` to the app or `URLSession`/sockets outside the helper
  (`scripts/check-entitlements.sh` and `NetworkHelperSourceTests` enforce it).
  The built-in llama.cpp engine is the only AI engine; there is no AI server.
- **Apple Intelligence is intentionally disabled** via
  `Integrations.appleIntelligenceBlocked = true` (kept provably on-device). Don't
  re-enable without being asked.
- No third-party GitHub marketplace Actions; first-party deps only (weak supply
  chain is a hard no).

## CI / release
- Repo is **public → unlimited free standard runners incl. macOS**. Only "larger"
  (`-xlarge`) runners are billed. macOS runners can't be swapped for Linux.
- Runner-quota failures look like real CI failures: **job never ran, logs 404**.
  Don't treat that as a code regression.
- **CHANGELOG.md is generated by CI — never hand-edit it.** Manual edits cause
  merge conflicts across PRs. Versioning is conventional-commits → semver.
- `scripts/scan-secrets.sh` is a fail-closed leak gate (secrets + PHI filenames).
  Its `git grep` uses `-e "$PATTERN"` because patterns start with `-----BEGIN`.

## Conventions
- **Names on out-of-app surfaces go through `PatientLabel`** (initials by default;
  full name only with the opt-in and while unlocked). `scripts/check-patient-label.sh`
  and `PatientLabelTests` scan notifications, the menu bar, Spotlight, Intents,
  Calendar and Reminders.
- **Colors come from `Theme`** (`Sources/App/Views/Theme`), backed by named
  colors in `Assets.xcassets/Theme` (light, dark, Increase Contrast). No color
  literals or system colors in screens; add a colorset + `Theme` token +
  `Theme.all` entry (and a `pairings` entry if text sits on it). Controls use
  the kit in `ThemeComponents.swift`. Light/Dark/System is `NSApp.appearance`.
- **Text goes through the Theme text kit** (`ThemeTextField`, `ThemeTextArea`,
  `TextField.patient`, `PatientTextView`, `.selectablePatientText()`), which keeps
  macOS Writing Tools off. `WritingToolsBlockTests` rejects raw `TextField`,
  `TextEditor`, `SecureField`, `.textSelection` and `NSTextView` subclasses outside
  `Views/Theme`, except in its allowlist of files with no patient data.
- `AppSettings` pattern: UserDefaults-backed, `private enum Keys`,
  `@Published var x { didSet { defaults.set(...) } }`, all loaded in `init`.
- Repo **auto-deletes head branches on merge**; merging a base branch closes its
  child PRs. Sequence PRs to avoid CHANGELOG/shared-file conflicts.
- This Linux sandbox has **no Swift toolchain** (`swift`/`xcodebuild` absent):
  can't run XCTest here. Validate with bash tests + close review; CI compiles.
